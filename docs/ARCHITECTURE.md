# Architecture

Current implementation: 2026-09-27. React 19 + TypeScript + Vite, Zustand and one persistent React Three Fiber canvas. The authorized direct-flight game supersedes the original narrative-scroll descent. Scope stays prologue, Apollo 11, and the Mars signal teaser.

## Journey and flight

`src/App.tsx` owns the full-viewport journey and shared inspector. `src/Journey.tsx` supplies arrival, the footprint walk prompt and one optional random NASA-sourced quiz. Incorrect answers explicitly say "Oops, not quite" before giving the correct fact. Hardware remains unnamed until scanning. Six discoveries gate the ending.

`src/game/flight.ts` is a pure simulation with fixed substeps and a 100ms frame cap. Initial position is x=0, z=20, altitude=100; the landing circle is at the origin. Manual control is the default on launch, retry and restart. Horizontal input requests a speed up to 3.8 game metres/second with responsive release damping; it never automatically recenters. Manual descent settles toward 5.5m/s. Holding Space/brake slows descent toward 0.8m/s. Safe touchdown still requires position within radius 6, vertical speed below 3.5 and lateral speed below 3. Optional assist centers the craft and protects final alignment. These are fictional game controls, not flight engineering.

`src/game/input.ts` shares keyboard and pointer controls. Clear input on launch, retry, blur, pointer cancellation and dialog entry. `src/FlightHUD.tsx` retains the two instrument displays, measured telemetry, pause, opt-in assist and touch controls. World updates dispatch the `mersa-flight` event rather than rendering React on every frame.

`src/three/World.tsx` owns terrain, stars, rocks, lighting, target and camera. The player craft is visible throughout flight. A close forward-facing chase camera follows a larger craft through an authored approach corridor. Visual position uses altitude * 0.48 vertically and altitude * 1.7 added to forward range; this gives hills/parallax without changing the pure landing simulation. The HUD reports simulated landing alignment, not the full rendered corridor range. Terrain stays flat around the walking/site area. LandingDust.tsx provides a schematic ground-skimming plume below 16 m, frozen for reduced motion and pause. The old first-person `PilotCockpit.tsx` is retained as unused source, not mounted. `SurveyCraft.tsx` is authored fictional geometry. `Explorer.tsx` provides walking and surface camera; skip-walk is an accessible equivalent.

## Shared inspection

`src/stores/archive.ts` separates the current `selected` part (empty string means none) from `inspectedParts` (learning progress). Repeated selection deselects, clears isolation, hides the poster and removes the selection checkmark. Learning progress remains recorded until inspection closes. All three Eagle parts must still be visited to archive it. Opening inspection starts with nothing selected; cross-section is off on a fresh expedition.

`ApolloModel.tsx` loads local NASA-derived descent and full models with local Draco decoding. It groups structure, engine and gear, animates separation, and provides direct mesh and HTML-button selection. Original NASA materials are cloned without recoloring. Separate blue EdgesGeometry overlays outline selected mesh edges. Selection automatically animates that part outward; selecting it again returns it unless Separate hardware is active. Cross-section uses a clipping plane, not a modeled engineering interior. Full historical Eagle is the initial model on the surface and in inspection. An explicit See what remains today toggle switches to the descent stage; this choice persists across inspector exit and resets to full on restart. Inspection camera view offsets reserve room for the poster; exit restores the surface camera and artifact-button focus.

`PartPoster.tsx` supplies a small Miso quote, a real photograph, nine short teaching lines, a simplified equation and an official source for each of four lessons. Desktop text floats over the scene without a panel fill; a scrollable lower layout remains in the responsive CSS. Posters reset scroll on part changes. `PhotoReveal` reveals more of a real local photograph on hover, keyboard focus, or tap; explicit expansion shows the whole photo with its caption. No cropped concept-poster labels are presented as evidence.

The footprint photograph is fully visible immediately and can be archived without an exposure slider. Reflector alignment and the camera, seismometer and message reveals remain short schematic interactions. `src/data/archive.ts` separates verified facts from fictional alien interpretations.

## Apollo field guide

`src/Learning.tsx` implements one native scrollable dialog, opened by FIELD GUIDE after identification. It uses a light reading surface. MissionOverview.tsx adds mission goals, crew roles, six expandable dated milestones and surface science from the supplied NASA mission text. Sections also cover the lunar module, photography and actual Apollo guidance code. A visible surface CTA opens the same dialog in codeOnly mode, with a real repository screenshot linking to vscode.dev/github/chrislgarry/Apollo-11 (VS Code for the Web). It reuses the world underneath, never mounts a second canvas, pauses interaction, traps focus natively and returns focus to its opener on close/Escape. Closing the guide while inspecting leaves the inspector open. Section anchors stay inside the dialog; no narrative page scroll requires restoration.

All six photographs and three complete public-domain AGC source files are local under `public/learning`. `provenance.json` records image URLs and pinned repository commit. Code excerpts preserve original line numbers; topic buttons switch files, restrained highlights identify key lines, and clicking a line updates a plain-English note. Original-source links use the same pinned commit. The explorer does not execute Apollo software. Fetches are aborted when switching topics; failures provide a source-link fallback. Photos identify Apollo 13 training separately from Apollo 11.

## Motion, performance and access

Occasional decorative streaks and faint aurora-like glows are CSS overlays, identified as fictional in the field guide. They ignore pointers, stop when paused, disappear in inspection and are disabled for reduced motion. Reduced motion also skips camera/model interpolation and photo transitions without bypassing learning gates.

DPR is capped at 1.5; one shadow light and instanced rocks limit rendering cost. Assets and fonts are local; no runtime third-party media requests, backend, accounts or tracking. MissionAudio.tsx plays the supplied landing radio clip on the mersa-touchdown event when sound is enabled. SoundClip provides explicit native replay controls during walking and in footprints. Playing a clip enables sound and pauses other audio; global mute/pause stops it. Browser autoplay rejection is handled and replay remains available. These are historical recordings, not lunar environmental audio. Explorer.tsx uses NASA's generic static astronaut model, normalized to 2.4 scene units; it is not an exact Apollo suit or a rigged walking animation. Progress is in memory and resets on refresh. Native archive and field-guide dialogs scroll independently; the game page itself does not scroll.

## Validation

`npm run typecheck`, `npm run build`, `node tests/flight.cjs`, `npm run test:e2e` (Vite running). Tests cover manual/assisted handling at four frame rates; full desktop and mobile/reduced-motion journeys; wrong-answer correction; part deselection and inspection exit; first-click footprint access; guide photo/code interaction and focus restoration; failure/retry; and real keyboard/touch manual landings. Latest rendered captures: `docs/qa/immersive`. Current user requested desktop-only validation; mobile responsive styles remain but are not revalidated for this revision. Physical mobile hardware is not covered by browser emulation.

## Reusable hardware journey contract / current revision
`ScanTransition.tsx` owns a native overflow scroller and GSAP ScrollTrigger. Its 220vh track writes `scanProgress` (0..1) to the shared store. `ViewRig` interpolates the existing camera along an elevated approach and progressively reserves the reading-panel space. OrbitControls and spatial component labels activate after completion. Continue scan uses native smooth scroll; Escape/Return clears inspection. Reduced motion bypasses the transition. Inspector/field-guide scrollers remain independent; returning restores the surface camera and clue focus.

`PartPoster.tsx` retains the four nine-sentence sourced lessons, grouping their sentences into two paragraphs rather than numbered bullets. All future hardware lessons should reuse this warm-white reading component and include Miso, credited evidence, plain-English prose, a simplified relationship where useful, and a separate fictional interpretation. `ExpeditionLog.tsx` derives milestones and the latest record from real session discovery state; it opens the existing archive or field guide, without adding a progression gate.

`Explorer.tsx` normalizes the NASA static mesh, adds authored skin weights and a nine-bone skeleton (root, hips/knees, shoulders/elbows), and animates counter-swing, knee flexion and elbows while walking. It eases to rest and respects pause/reduced motion. This is approximate artistic skinning, not a NASA animation or exact Apollo suit. `LandingDust.tsx` uses four transparent, procedurally shaded ground sheets with layered noise; no solid particle geometry, image generation or physical fluid solver.

`ApolloModel.tsx` clones source materials and applies an authored gold/copper metallic treatment and procedural fine normal variation to named thermal-blanket materials; other untextured surfaces receive restrained metallic response. Source GLBs are unchanged. Blue selection edges stay separate. This supersedes the earlier requirement to preserve every rendered material unchanged.

Upper-shell meshes are classified by their world-space height before the legacy name mapping, so the ascent cabin belongs to Structure rather than being extracted with Landing gear. Dark insulation and silver shell surfaces are assigned separately. Astronaut leg weights exclude the lower backpack to keep its rigid housing stable during strides.
